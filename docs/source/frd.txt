Executive Summary
Companies that rent out high-value equipment lose revenue because they cannot see where each asset is, which repairs it has had, or what condition it came back in. Damage is described inconsistently, has no photo evidence, and is billed late, disputed, or never billed. This project builds a Rental Equipment Tracking and Condition Logging solution on SAP BTP using the Cloud Application Programming (CAP) Model (Node.js, TypeScript) with an SAP Fiori (Fiori Elements) back-office frontend and a mobile app for yard workers. The mobile app integrates with the device camera so photos of damage are captured at the moment of return and attached to the CAP backend. CAP calculates the repair charge and posts it automatically to SAP HANA for billing.
Expected Outcomes
Every asset has one trusted record: status, current location, custodian, and complete maintenance and condition history
Standardised return inspection with mandatory photo evidence, severity grading and A to D condition grade
Automated repair charge calculation and approval, with posting to S/4HANA (maintenance notification/order and billing request)
95% or more of returns with new damage result in a billing document; billing time under 15 minutes (auto-approved) or under 24 hours (approval needed)
50% fewer disputed damage charges within 6 months; fewer than 2% of assets without a location update in 24 hours
Scope
In Scope
CAP backend service (Node.js/TypeScript) with CDS models, business logic, outbox-based integration
SAP Fiori Elements back-office apps (List Report, Object Page, Analytical List Page) plus limited freestyle SAPUI5 (map, photo comparison)
Mobile app (Android/iOS, offline-first) with QR/barcode/NFC scan, in-app camera, inspection wizard, signature capture
OData v4 services exposed by CAP; REST endpoints for mobile sync and media upload
SAP HANA Cloud for persistence; SAP BTP Object Store for photos and video
XSUAA (or IAS) authentication with role-based and plant-based access
SAP Destination and Connectivity (Cloud Connector for on-premise) to HANA
HTML5 Application Repository for Fiori app hosting
Document Information Management (DIM) for generated damage report PDFs and signed documents (7-year retention)
Integration: equipment, customers and rental contracts from HANA; maintenance notifications, orders and billing requests to HANA; billing status back
Out of Scope (Release 1)
Live telematics/IoT tracking (data model is prepared for it)
AI-based automatic damage detection from photos
Customer self-service portal

Security & Authorization
Aspect
Requirement

OAuth 2.0 via XSUAA (Cloud Foundry); optional SAP Cloud Identity Services (IAS) with OIDC; MFA per customer policy; mobile uses PKCE and secure token storage
Roles
YardWorker (scan, inspect, transfer), Dispatcher (check-out, override with reason), Technician (repairs, release quarantine), BillingClerk (approve and dispute charges), Manager (all approvals, dashboards, overrides), Admin (configuration, user management), Auditor (read-only)

@requires at service and entity level; instance-based filter on Plant (assets, inspections, charges); price data hidden from YardWorker
Mobile Security
Certificate pinning; encrypted local database and file store; remote wipe via token revocation; MDM support
Data Encryption
TLS 1.2+ in transit; HANA Cloud and Object Store encryption at rest
Evidence Integrity
SHA-256 hash, immutable inspections, signed URLs, versioned bucket, legal-hold flag
Audit
All write actions logged (CAP eventing to audit table); immutable and exportable
Compliance
GDPR / local data-protection law (retention, subject access, deletion of personal data without deleting financial evidence); OWASP ASVS L2 and MASVS
